Notes / AI foundations / Who actually runs Claude on a cloud?

Whether the cloud or Anthropic runs Claude depends on which cloud product you pick.

The short version

  • What I tried: reading the AWS, Google, Microsoft and Anthropic documentation to trace how a Claude request is actually served on each platform.
  • What happened: on Bedrock, AWS runs the model in accounts it owns and Anthropic cannot see inside them. On Foundry there are two versions of Claude, and one runs on Anthropic's own infrastructure. That makes at least four hosting arrangements across three clouds.
  • What I would do next: send one prompt through two platforms and compare features, latency and logging.

The problem and the context

When a team says "we use Claude on Bedrock", it sounds like a proxy: Bedrock forwards the request to Anthropic. That is not how it works, and the difference matters for security reviews, data residency and which features you get. I wanted a plain account of what hosting a frontier model on someone else's cloud involves.

This is desk research. Nothing was deployed, and the vendors do not publish everything, so the last section lists what I could not confirm.

How Bedrock hosts a Claude model

AWS documents the mechanism in its data protection guide. The steps, as far as they are public:

  1. The provider delivers the model to AWS. Anthropic hands over the model it wants served.
  2. AWS copies it into a deployment account. Each AWS Region where Bedrock runs has one model deployment account per model provider. The Bedrock service team owns and operates these accounts. AWS says it makes a deep copy of the provider's inference software into them.
  3. The provider is locked out. Providers have no access to those accounts, so they cannot see Bedrock logs, prompts or completions. This is the main difference from calling a provider's own API.
  4. Your call stays inside AWS. You call the bedrock-runtime endpoint with a model ID, usually through the Converse API, which gives one request format across providers. Invocation traffic stays on the AWS network. Bedrock runs automated abuse detection, and AWS says no human reads your inputs or outputs.
  5. Routing can cross Regions. If you use an inference profile instead of a plain model ID, Bedrock picks a destination Region. Geographic profiles stay within a region group and global profiles can go to supported Regions worldwide. Profile IDs carry a prefix, such as global.anthropic.claude-sonnet-4-5-20250929-v1:0. Inference profiles do not work with Provisioned Throughput.

AWS also describes a newer serving layer, Mantle, which exposes OpenAI-compatible endpoints. AWS says it is built so that no operator can reach customer prompts, whether from AWS, the customer or the model provider. I could not find that claim on the main data protection page, so treat it as a separate, newer design.

Why one model can sit on three clouds

Anthropic says it trains and runs Claude on AWS Trainium, Google TPUs and NVIDIA GPUs, and that Claude is the only frontier model available on all three large cloud platforms. Running on several kinds of hardware is what makes it practical to hand a model to several clouds, each with its own accelerators and serving stack. It also means a cloud can host the model on its own infrastructure and bill you in its own units.

Which chips serve a given Bedrock request is not public, and I would not assume it from Anthropic's training partners.

What it means in practice

  • Ask "who operates the inference" as a separate question from "which cloud do we pay". Answers differ even inside one vendor.
  • Check the feature list for the platform you pick. The first-party Claude API is the reference, and Vertex and Foundry each leave some features out.
  • Model IDs differ by platform. Vertex used @ before the snapshot date on older models, and Bedrock adds a region prefix for inference profiles.
  • Read data residency per product. One news report said Foundry's Azure-hosted deployments run in Sweden under a Global Standard type that can serve from anywhere, so European residency guarantees that apply on Bedrock or Vertex may not carry over.

What I could not confirm

  • The exact contract and delivery format between Anthropic and each cloud. AWS says "model" and "inference software", and says nothing more about the artefacts.
  • Which hardware serves a request on each platform.
  • How far the Mantle zero-operator-access design applies to Claude models on Bedrock today.
  • Current retention rules per model. AWS points to separate pages for retention and abuse detection, and I did not read them in full.

What I would change

I started with the picture of a cloud as a pass-through to Anthropic. After reading the docs I would describe Bedrock as a hosting service in which AWS operates the model, and drop the pass-through picture entirely. For Foundry the picture splits in two, so the post needs a table instead of one sentence.
